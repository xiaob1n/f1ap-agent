# F1AP Agent 阶段执行计划

状态：2026-10-26，**待执行批准，已同步 API 11 表精简版；不做预算限制，只记录成本**。未创建应用、连接服务器或执行付费模型调用。

## 从这里开始

跨端实施先后、可并行任务和联合验收见 [执行顺序报告](../../f1ap-api/docs/execution-order.md)。本文件定义阶段内容，对端联调依赖不表示必须等待对端整个阶段先完成。

1. 阅读 [API 契约 v1](../../f1ap-api/docs/phase-plan.md#跨端契约-v1) 与 [数据设计](../../f1ap-api/docs/database-design.md)。当前执行标识统一为 run_id，题目行 ID 已包含版本，不继续使用旧 job/attempt/item 实体。
2. 获准实施后与 API A0 一起冻结依赖/契约，先用固定输出完成无模型费用回环。
3. 各阶段记录实际测试和费用；涉及现有服务、付费调用或部署时取得适用授权。下文路径均为拟建交付物。

## 1. 固定边界

Python 3.12、LangGraph、单 Agent 实例、Chroma 内嵌持久化、云端生成与 Embedding API。RabbitMQ 收任务回结果；只通过 OpenF1 API 获取赛事数据，不直连 MongoDB，不写业务 MySQL，不接 Nacos。

Agent 不采集官方题目/答案、不提交官网、不直接向前端推送。全文/切片/向量保存在受控 Agent 存储，MySQL 只收元数据及必要证据。统一后台计算，不按访客调用。预算方面不做限制：不申请金额许可、不按累计费用降频或停机；任务身份、超时、截止和防无限循环的调用次数由 Java 下发。

## 3. B0：版本与契约

拟建 `pyproject.toml`、`src/f1ap_agent/`、`tests/`、`docs/dependency-matrix.md`。

1. 验证 Python 3.12 与 LangGraph、Chroma、结构化校验、MQ/HTTP 客户端和候选云端 SDK 的版本交集，选择可复现的依赖锁定工具。
2. 使用 API `contracts/v1/` 的同一版 Schema 与样例；校验 run_id/question_id、option_key、UTC 毫秒时间、Decimal 字符串和哈希一致性，不自建不兼容协议。
3. 模型供应商封装在适配层，尚未指定时用 mock，不伪装真实结果；不默认增加 FastAPI、Celery 或任意代码执行工具。

**验收**：两端同一消息结论一致；测试无需密钥；任务无 Answer；未选供应商不启动付费调用或默认 Embedding 模型。

## 4. B1：Worker 与恢复

拟建 `worker/`、`messaging/`、`runtime/`。

1. 单进程、初期 prefetch=1，验证消息、run_id、task_key/attempt_no、时间、call_limit 和哈希，不申请金额许可。重投同 run 不是新尝试；失败重试由 Java 新建 run_id；新的滚动窗口使用新的 task_key，不能误判为重复消息。
2. 持久卷内以 run_id 组织单写入者执行日志、调用意图和待发事件。用标准库文件日志、同步落盘与原子替换实现最小恢复，不新增数据库；日志损坏/遗失时失败关闭，交 Java 确认状态。
3. 调用前本地持久记录 call_key 和 CALL_STARTED，完成后记结果/费用，再通过 MQ 异步交给 Java。中间崩溃视为 UNKNOWN，不自动重复相同副作用；金额未知本身不阻止其他合法任务，结果可以先完成、成本后对账。
4. 必需结果、初始用量状态及 finished 事件先持久化，使用 mandatory 发布，关联处理 return、nack、confirm 及通道断开。只有 confirm 成功且消息未被 return，才可标记本次发送成功；全部必需事件满足条件后 ACK 原任务。不等供应商最终账单，初始费用可为 UNKNOWN。不可路由时保留待发文件，有限退避/告警，不以 confirm 单独 ACK 原任务；恢复绑定后重发原 event_id。Broker 确认不代表 Java 已提交业务事务，Java 仍需 Inbox 和提交后 ACK。

**验收**：同 run 三次交付不重复执行收费步骤；新窗口任务正常运行。删除回包队列绑定，确认 Agent 即使收到 confirm 也不 ACK 原任务；恢复绑定后旧 event_id 安全重发。nack、通道关闭和确认丢失均保留待发事件。调用中崩溃保留 UNKNOWN；过期任务和丢失日志不继续调用模型；费用未知不会变成全局预算闸门。

## 5. B2：OpenF1 与领奖台

拟建 `data/openf1/`、`features/`、`baselines/`。

1. 采用显式 meeting/session 配置和受控 API 工具，限制端点、参数、查询范围、响应大小、超时；本轮不开展自动赛事映射，不偷偷访问 MongoDB。
2. 核验字段、单位、缺失和数据可得时间；清洗无效圈、进出站圈、轮胎/天气等可比性因素，未知燃油量明确作为限制。
3. 基于冻结特征建立可解释领奖台统计基线，记录方法/样本/先验/随机种子；保存输入清单和证据哈希，用确定性解释先完成 A4。

**验收**：空数据/缺失/单位不符有明确失败状态；名次概率有一致性检查；推荐不重复车手；首条链路不调用真实模型。

## 6. B3：十题适配

| 题目组 | 主要边界 |
| --- | --- |
| Q1/Q7/Q9/Q10 | 共享正赛结果分布；候选排名、区间和冠军联合条件，不把相关概率直接相乘 |
| Q2/Q3/Q4 | 排位/晋级分布；Q3 最快不等于处罚后发车第一；两车联合晋级 |
| Q5 | 最快圈与轮胎/策略相关，不直接等同冠军 |
| Q6 | 最快进站口径，不把维修区总耗时误作服务时间 |
| Q8 | 四车分类完赛计数；当前 0–4 有限候选，非自由数值 |

1. 为各题建立特征、概率事件、方法假设、数据不足标准，复用共享特征。
2. 写正常、缺数据、候选均无有效成绩和未知规则用例；不得读当前来源 Answer 作为预测输入。
3. 使用模拟时记录分布、种子、样本数和误差，保存可重放摘要，不向 MQ/MySQL 塞全量样本。新题语义进入明确未知分支，模板 ID 不作为唯一路由。

**验收**：逐题数据和规则可追溯；Q6/Q8 口径通过；Q10 联合极端场景可验证；不能支持的题明确报告，不用 LLM 猜测填满。

## 7. B4：图编排与单题 JSON

拟建 `graph/`、`strategies/`、`schemas/`。

1. 固定流程：校验 → 分类 → 时间/质量 → 特征 → 可选新闻 → 概率 → 策略 → 解释 → 输出校验；普通计算节点不调用模型。
2. 同一概率计算积分优先及已确认目标，按规则验证数量、顺序、候选键唯一性、NUMERIC 精度/范围。切换策略不重跑图。
3. 每题输出一个完整的规范化结果：概率、多策略推荐、引用证据及状态，明确 run_id/question_id；失败也给终态，finished 列出全部应处理题目。不再单独发送概率/推荐/证据子表对象。
4. 限制节点、工具和模型调用次数；恢复依赖 B1 日志，不因用了 LangGraph 就声称跨容器 checkpoint 已实现。新一次正式计算使用新的 run_id。

**验收**：结果 Schema 与 API 内嵌 JSON 契约一致；无重复候选/策略；输出可独立复算；单题失败不取消其他题；没有假成功或无限循环。

## 8. B5：新闻与 Chroma

拟建 `news/`、`rag/`、`storage/`。

1. 先确定允许的来源和使用范围，由 Java 发 NEWS_REFRESH 执行，增量采集、URL/内容哈希去重；全文仅在 Agent 受控文件中保存。
2. 内容变化追加版本，保留发布时间、首次观测时间和哈希；按预测截止过滤证据，不用后改新闻回填历史。
3. 显式使用云端 Embedding，入库和查询向量调用都记录用量/成本，不经过金额额度审批。固定模型/维度/距离/切片/collection 版本，换模型新建集合，不混用向量。
4. Chroma 同一路径仅一个写进程；发送 document_key 和索引元数据，不传全文。引用片段及检索版本随单题 evidence 冻结。

**验收**：重复内容不重复向量化；晚到内容被过滤；重建容器索引仍在；Embedding 故障保留旧索引并标新鲜度；新闻文本不能改变工具权限。

## 9. B6：生成模型与费用

拟建 `models/`、`cost/`、`evaluation/`。

1. 先 mock，在供应商接入及真实调用获准后做有界测试；不是逐笔金额审批。价格可得时记录价格版本，暂不可得则先记录用量与未知成本，不因缺少报价触发预算拒绝。LLM 负责受限抽取、解释，不能直接把自报置信度作为概率。
2. 每次调用检查 run 的 call_limit、任务截止和租约；关闭隐藏重试或单独记账。UNKNOWN 不记零，不自动换供应商绕过已批准的供应商配置；把 call_key/usage_revision 用量与成本经 MQ 回传，旧预测被拒不等于成本记录可以丢弃。金额高低不阻止其他合法任务。
3. 新闻修改概率必须通过可检验特征；否则仅作解释/风险提示。按时间比较基线、积分、覆盖率与适用概率指标，历史结果可能被 LLM 记忆，因此补充前瞻验证。

**验收**：供应商错误、429、断线未知成本和非法输出有有限处理；解释不改推荐、不伪造来源。实际成本高于估计、累计支出较高、跨月或金额 UNKNOWN 均不触发预算停机；call_limit、截止和重试次数仍有效。访客数量不增加调用数。

## 10. B7：部署与恢复

拟建 `Dockerfile`、`docs/runbook.md`，统一 Compose 由 API A7 管理。

1. 固定镜像与依赖，环境注入配置，不接 Nacos；不挂载 API 含 Answer 的原始文件卷。
2. 持久保存 Chroma、新闻、特征清单、执行日志及待发事件，明确资源限制、备份和停止行为；健康检查不调用模型。
3. 获准后演练进程中断、MQ 断连、未知成本、索引备份恢复、旧 run 拒收和供应商错误；状态损坏失败关闭，不重新执行旧收费调用。

**验收**：重建不丢索引/日志；单写进程约束成立；晚到费用可对账；无匿名 Agent 公网入口；恢复证据真实可复查。
